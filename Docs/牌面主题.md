# 牌面主题说明

把「棋盘上用什么图」从场景引用里解耦出来。换主题 = 换一个目录，不用改代码、不用改场景。

## 目录约定

```
Assets/Resources/TileThemes/
├── themes.json            主题清单（默认主题写在这里）
└── shanhai/               主题目录，名字即主题 id
    ├── 0.png              文件名即牌面 id，0 ~ 35
    ├── 1.png
    └── … 35.png
```

运行时由 `Assets/Scripts/Theme/TileThemeManager.cs` 用 `Resources.LoadAll` 读整个目录，
按文件名建索引，所以新增主题不需要在 Unity 里做任何拖拽绑定。

## 新增一套主题

1. 建目录 `Assets/Resources/TileThemes/<新id>/`；
2. 放入 `0.png` ~ `35.png`，要求：
   - 256 × 256，PNG，带透明通道；
   - **底板直接画在图上**（整幅铺满），不要留透明边——棋盘后面还有一层 `itemback`，
     图不满幅就会露出旧主题的粉色边框；
   - 画风自行决定，但 36 张要统一；
3. 在 `themes.json` 的 `themes` 数组里加一条 `{ "id": "新id", "name": "显示名" }`；
4. 想让它成为默认，把 `defaultTheme` 改成新 id。

## 切换主题

- 运行时：`TileThemeManager.SetTheme("新id")`，写进 PlayerPrefs 的 `tile_theme_id`；
- 回到默认：`TileThemeManager.ResetToDefault()`；
- 取当前 id：`TileThemeManager.ActiveId`。

## 取图规则

`Pokemon.GetSprite(name)` 先问主题，主题没有再回落到场景里原有的精灵列表，所以：

- 主题只需要提供 36 张牌面，`stone3d`、`Crate`、`IceBox` 这些特殊牌会自动走原逻辑；
- 旧的三种皮肤（经典 `a` / 可爱 `d` / 新版 `b`）会被统一映射到同一张主题图：
  取 `"3a"` 时先找 `3a.png`，找不到就去掉尾部字母找 `3.png`；
- 所以一套图可以同时服务三种皮肤，不必须备三份。

## 分支约定：一个分支 = 一个游戏

本仓库不做合并。每条分支就是一款独立游戏，换游戏切分支即可：

```bash
git checkout main                            # 工程底座
git checkout -b feature/tile-theme-xxx        # 新主题另开一条
```

- 分支各自演进、各自推送，**不合回 `main`**；
- `main` 只维护工具层与通用系统，作为新分支的起点；
- 一款游戏定稿后建议打 tag（`git tag shanhai-1.0 && git push origin shanhai-1.0`），便于回溯。

## 重新生成图片

图片由脚本绘制，不是手绘素材：

```bash
python Tools/tile_theme/make_tiles.py
```

脚本会覆盖 `Assets/Resources/TileThemes/shanhai/*.png`，并在 `Temp/` 下产出
`sheet_shanhai.png`（36 张拼图）和 `compare_stack.png`（叠底板对比）用于检查。
改配色改脚本顶部的常量，改图案改对应的 `i_xxx()` 函数。

## 注意

- `themes.json` 用 `JsonUtility` 解析，字段名必须与 `TileThemeManifest` 一致；
- 牌面 id 上限来自 `GameConfig.total_pokemon_kind`（当前 36），新增主题时图片数量不要少于这个值；
- 主题目录里的图会被打进包体，一套 256 × 256 约 300 KB 上下，注意总量。
