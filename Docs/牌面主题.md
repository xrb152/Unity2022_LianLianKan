# 牌面主题说明

把「棋盘上用什么图」从场景引用里解耦出来。换主题 = 换一个目录，不用改代码、不用改场景。

## 目录约定

```
Assets/Resources/TileThemes/
├── themes.json            主题清单（默认主题写在这里）
└── xianzhou/              主题目录，名字即主题 id
    ├── 0.png              文件名即牌面 id，0 ~ 35
    ├── 1.png
    └── … 35.png
```

运行时由 `Assets/Scripts/Theme/TileThemeManager.cs` 用 `Resources.LoadAll` 读整个目录，
按文件名建索引，所以新增主题不需要在 Unity 里做任何拖拽绑定。

## 新增一套主题

1. 建目录 `Assets/Resources/TileThemes/<新id>/`；
2. 放入 `0.png` ~ `35.png`，要求：
   - 256 × 256，PNG，带透明通道；
   - **底板直接画在图上**（整幅铺满），不要留透明边——棋盘后面还有一层 `itemback`，
     图不满幅就会露出旧主题的粉色边框；
   - 画风自行决定，但 36 张要统一；
3. 在 `themes.json` 的 `themes` 数组里加一条 `{ "id": "新id", "name": "显示名" }`；
4. 想让它成为默认，把 `defaultTheme` 改成新 id。

## 切换主题

- 运行时：`TileThemeManager.SetTheme("新id")`，写进 PlayerPrefs 的 `tile_theme_id`；
- 回到默认：`TileThemeManager.ResetToDefault()`；
- 取当前 id：`TileThemeManager.ActiveId`。

## 取图规则

`Pokemon.GetSprite(name)` 先问主题，主题没有再回落到场景里原有的精灵列表，所以：

- 主题只需要提供 36 张牌面，`stone3d`、`Crate`、`IceBox` 这些特殊牌会自动走原逻辑；
- 旧的三种皮肤（经典 `a` / 可爱 `d` / 新版 `b`）会被统一映射到同一张主题图：
  取 `"3a"` 时先找 `3a.png`，找不到就去掉尾部字母找 `3.png`；
- 所以一套图可以同时服务三种皮肤，不必须备三份。

## 分支约定：一个分支 = 一个游戏

本仓库不做合并。每条分支就是一款独立游戏，换游戏切分支即可：

```bash
git checkout main                            # 工程底座
git checkout -b feature/tile-theme-xxx        # 新主题另开一条
```

- 分支各自演进、各自推送，**不合回 `main`**；
- `main` 只维护工具层与通用系统，作为新分支的起点；
- 一款游戏定稿后建议打 tag（`git tag xianzhou-1.0 && git push origin xianzhou-1.0`），便于回溯。

## 重新生成图片

图片由脚本绘制，不是手绘素材：

```bash
python Tools/tile_theme/make_tiles.py
```

脚本会覆盖 `Assets/Resources/TileThemes/xianzhou/*.png`，并在 `Temp/` 下产出
`sheet_xianzhou.png`（36 张拼图）用于检查。
改配色改脚本顶部的常量，改图案改对应的 `i_xxx()` 函数。

## 注意

- `themes.json` 用 `JsonUtility` 解析，字段名必须与 `TileThemeManifest` 一致；
- 牌面 id 上限来自 `GameConfig.total_pokemon_kind`（当前 36），新增主题时图片数量不要少于这个值；
- 主题目录里的图会被打进包体，一套 256 × 256 约 300 KB 上下，注意总量。

## 背景

棋盘外的两张背景图跟着主题一起换。不走代码，直接换贴图：

| 文件 | 用在哪 | 引用方式 |
|---|---|---|
| `Assets/Images/MainSence/back1.png` | `Main.unity` 的 `MainPanel` | UI Image，Simple + 拉伸铺满 |
| `Assets/Images/playUI/playBg.png` | `GamePlay.unity` / `Help.unity` 的 `BgOne` | SpriteRenderer + `BackgroundController` cover 缩放 |

换图的硬约束：

- 尺寸固定 1920 × 1080，**不要动同名 `.meta`**——guid 不变，场景引用就一行都不用改，Unity 切回窗口会自动重新导入；
- 整幅不透明、不留透明边（`spriteMeshType: Tight` + `alphaIsTransparency: 0`，留透明边会改变 Sprite bounds）；
- `playBg` 是 cover：`BackgroundController` 取 `perX/perY` 的较大者做缩放，宽屏手机会裁掉左右两侧，重要内容不要贴边；
- `back1` 是拉伸铺满（`PreserveAspect: 0`），从 5:3（800 × 480 参考分辨率）到 21:9 之间会被横向拉伸，别画正圆和精确几何。

重画：

```bash
python Tools/bg/make_bg.py           # 预览 -> Temp/bg_new_main.png、Temp/bg_new_play.png
python Tools/bg/make_bg.py --apply   # 覆盖上面两张原图
```

画面是纯 PIL 绘制的扁平插画，主题「莲池水乡」：

- **主界面**（`back1.png`）：粉紫天光从 `#F6E5F4` 渐变到 `#428886`，两层很淡的青色远岸剪影（`#B0C6D0` / `#96B8C0`），
  水层从山脚一路铺到画布底部（**不要让它中途结束，否则出现横向接缝**），池面同心涟漪 + 碎光，
  左右两组荷叶、荷花与花苞、一叶尖头小舟（`W*0.26 × H*0.158`），漂几片落叶。
- **游戏内**（`playBg.png`）：同色系压暗，`#1E3C3C` → `#09181C`，中央柔光（peak 74）托住米色牌面，
  顶部一点天光避免上沿发死，底部 8 片荷叶丛（缺口角度必须朝画面外，否则会被画布下沿切出尖角像山峰），
  荷叶上缘补一道冷光弧。

配色与牌面同源：墨青 `#1C3A38`、玉白 `#FAF5EA`、青绿 `#40AA9A`、荷粉 `#F6B2C8`。

画面里**不要出现正圆和精确几何**——`back1` 是横向拉伸的，圆形会被拉成椭圆。

## 主标题「闲舟静泛清波」

`Assets/Images/MainSence/Appname.png` 也是脚本生成的（1358 × 840 RGBA，两行竖排）：

```bash
python Tools/title/make_title.py           # 预览 -> Temp/title_preview/Appname.png
python Tools/title/make_title.py --apply   # 覆盖 Appname.png
```

改文案/换行改脚本里的 `JOBS`，`lines` 每项是 `(文字, 目标宽度占比, 该行最大高度占比)`：

```python
lines=[("闲舟静泛", 0.80, 0.500), ("清波", 0.455, 0.460)],
fill=((228, 252, 242), (48, 158, 138)),   # 极浅薄荷 -> 青绿
```

要留意两点：

- `WHITE_R`（白描边占字号的比例，当前 0.082）越大字越"胖"，两行间距必须按 `(上描边 + 下描边) * 1.35`
  算，直接用 `size * 0.12` 会重叠；脚本里有 `total_h > h * 0.94` 的断言兜底；
- 外发光笔宽别超过 `size * 0.07`，再大就变成一圈毛边。

弹窗那几张中文图（`popup/levelcomplete`、`popup/pause`、`popup/savemenow`、`popup/youlose`、`ranking/RANKING`）
是蓝色卡通字 + 白描边，跟主题色不冲突，换主题不用动。
