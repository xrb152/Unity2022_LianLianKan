# 牌面主题系统（基座说明）

本仓库的分支模型是**一个分支一款游戏**，`main` 只放与具体游戏无关的基座。
这个主题系统就是基座的一部分：它把「牌面用哪套图」从场景引用里解耦出来，
让每款游戏只要换一个资源目录，不必再改场景 YAML 或代码。

## 目录结构

```
Assets/
├── Scripts/Theme/TileThemeManager.cs     主题加载器（静态类）
└── Resources/TileThemes/
    ├── themes.json                       清单：默认主题 + 主题列表
    └── <主题id>/                         牌面图，文件名就是牌面 id
        ├── 0.png
        ├── 1.png
        └── … 35.png
```

`main` 上 `themes.json` 是空清单（`defaultTheme` 为空），因为基座不带具体游戏素材。
各游戏分支自行填入自己的主题。

## 取图规则

`Pokemon.GetSprite(key)` 先问主题：

1. 按原名精确匹配（`3a` → `3a.png`）；
2. 找不到就去掉尾部皮肤字母 `a`/`b`/`d` 再试（`3a` → `3.png`）；
3. 都没有则回落到场景里原有的 `_sprites` 列表（`stone3d`、`Crate`、`IceBox` 等特殊牌走这条）。

所以**一套图可以同时服务经典/可爱/新版三种皮肤，不用画三份**，
而且主题没覆盖的特殊牌不会因为换主题而丢图。

## 新增一套主题

1. 建 `Assets/Resources/TileThemes/<新id>/`，放 `0.png` ~ `35.png`；
2. `themes.json` 的 `themes` 数组加一条 `{ "id": "新id", "name": "显示名" }`；
3. 让默认生效：改 `defaultTheme`，或运行时调 `TileThemeManager.SetTheme("新id")`。

代码和场景都不用动。图必须是**满幅**的（见下）。

## 两个坑

- **牌面有两层底板**：贴图本身不带底板的情况下，后面还压着独立对象 `itemback`
  （`Assets/Images/SpecialItem/item_back1.png`，粉色带洋红边）。
  主题图如果不是满幅卡片，旧底板会从四周透出一圈粉色，与新配色脏在一起。
  所以主题图请画满整张画布。
- **牌面 id 上限**来自 `GameConfig.total_pokemon_kind`（当前 36），
  图片数量不要少于这个值，否则缺的那几张会回落到旧皮肤，风格不统一。

## 导入设置

牌面图按 Sprite 导入，并把 `spriteMeshType` 设为 **FullRect**（0）：
Tight 会自动裁掉透明边，导致不同牌面在图集里尺寸不一，摆到棋盘上被拉伸变形。
